# AI任务系统图片错乱问题修复计划

## 问题分析

用户反馈"任务完成后生成的图片和结果图错乱了"。经过代码审查，发现以下根因：

### 根因1：FetchPendingTask 竞态条件（最关键）

`AiTaskService.cs:137-164` — `FetchPendingTask()` 方法先查询再更新，**不是原子操作**：

```csharp
var pendingTask = Queryable().Where(x => x.Status == "pending").OrderBy(x => x.Create_time).First();
pendingTask.Status = "processing";
Update(pendingTask);
```

当多个 N8N worker 同时调用 `/ai/task/fetch` 时：
- Worker 1 读取到任务A（pending）→ 开始处理
- Worker 2 也读取到同一个任务A（仍是pending）→ 也开始处理
- 两个 worker 对同一张图生成不同结果
- 后写入的结果覆盖先写入的 → **图片错乱**

### 根因2：结果上传无状态校验

`UploadBase64Image()`（第210行）和 `UploadResultImage()`（第169行）**不检查任务是否为 processing 状态**。任何调用者都能为任何任务上传结果，包括已完成或失败的任务。

### 根因3：重试无状态保护

`RetryTask()`（第312行）将状态重置为 pending，但**不检查任务是否正在被 N8N 处理**。如果用户在 N8N 处理中点击重试，任务会被再次拉取，导致并发处理。

### 根因4：文件写入无并发保护

`UploadBase64Image()` 使用 `File.WriteAllBytes()`（第242行），`UploadResultImage()` 使用 `FileStream`（第192行）。并发写入同一文件路径可能导致文件损坏。

---

## 修复方案

### 修复1：FetchPendingTask 原子化（AiTaskService.cs）

将"查询+更新"改为原子操作，使用 SQL `UPDATE ... WHERE Status='pending'` 一次性完成：

```csharp
public N8nFetchTaskDto FetchPendingTask()
{
    // 原子操作：找到最早的pending任务并直接更新为processing
    var updatedTask = Context.Updateable<AiTask>()
        .SetColumns(x => new AiTask { Status = "processing", ProcessStartTime = DateTime.Now })
        .Where(x => x.Status == "pending")
        .OrderBy(x => x.Create_time)
        .ExecuteReturnEntity();  // 返回更新后的实体

    if (updatedTask == null) return null;

    return new N8nFetchTaskDto
    {
        TaskNo = updatedTask.Id,
        InputImageUrl = updatedTask.InputImagePath,
        Prompt = updatedTask.Prompt,
        ExtParams = updatedTask.ExtParams
    };
}
```

如果 SqlSugar 版本不支持 `ExecuteReturnEntity()` 配合 `Where`，改用 SqlSugar 的 `Updateable` + `Where` + `ExecuteCommand()` + 重新查询的方式，或使用数据库锁。

### 修复2：结果上传添加状态校验（AiTaskService.cs）

在 `UploadBase64Image()` 和 `UploadResultImage()` 中增加状态检查：

```csharp
// 在查询 task 之后，保存文件之前
if (task.Status != "processing")
{
    throw new CustomException($"任务状态不允许上传结果（当前状态: {task.Status}）");
}
```

### 修复3：重试添加状态校验（AiTaskService.cs）

在 `RetryTask()` 中增加状态检查：

```csharp
if (task.Status == "processing")
{
    throw new CustomException("任务正在处理中，请等待完成后再重试");
}
```

### 修复4：回调添加状态校验（AiTaskService.cs）

`CallbackSuccess()` 已有状态检查（第271行），确认保持即可。`CallbackFailed()` 也应增加检查，避免覆盖已完成任务的结果：

```csharp
// CallbackFailed 中增加
if (task.Status == "done")
{
    logger.Warn($"回调忽略: 任务已完成 taskNo={taskNo}");
    return false;
}
```

## 验证方式

1. 启动后端 `dotnet watch --project ZR.Admin.WebApi run`
2. 提交多个 AI 任务
3. 模拟 N8N 并发调用 `/ai/task/fetch`（可用 curl 或 Postman 同时发起多个请求），验证每个任务只被拉取一次
4. 验证结果上传时如果任务状态不是 processing，会返回错误
5. 验证处理中的任务不能被重试
6. 查看 NLog 日志确认无异常
